# Agent 答案质量 · 重复运行稳定性（2026-08-03）

## 结论

对 3 个多步 retrieval case 各重复运行 5 次（共 15 次真实 Agent + Judge 调用），15 次里只通过 2 次。

**这直接推翻了同一天单次运行得到的 90% 通过率**：在那次单跑里，本报告的 3 个 case 有 2 个通过；重复运行后其中 1 个是 0/5，另一个是 2/5。单次通过率不能作为答案质量的判断依据。

| Case | 通过率 | groundedness 区间 | 判定 |
|---|---:|---|---|
| `chroma_vs_qdrant` | 0/5 | 2–3（均值 2.4） | 稳定缺陷 |
| `agent_framework_multi_source` | 0/5 | 2–3（均值 2.8） | 稳定缺陷 |
| `paged_attention` | 2/5 | 3–4（均值 3.4） | 阈值边缘抖动 |

## 运行信息

- 命令：`uv run python -m agent_app.scripts.evaluate_agent_answers --only paged_attention,chroma_vs_qdrant,agent_framework_multi_source --repeat 5`
- Agent / Judge 模型：`kimi-k2.6`（同模型，存在自评偏差）
- 原始 JSON：`agent/experiments/runs/judge/20260803-102133.json`（默认被 Git 忽略）
- 通过规则：retrieval 类四项分数均需 ≥4

## 逐次结果

### `chroma_vs_qdrant`（0/5）

| 运行 | 相关性 | 完整性 | groundedness | Agent 耗时 |
|---|---:|---:|---:|---:|
| 1 | 5 | 5 | 3 | 118s |
| 2 | 2 | 2 | 2 | 96s |
| 3 | 5 | 5 | 3 | 84s |
| 4 | 2 | 2 | 2 | 128s |
| 5 | 2 | 2 | 2 | 116s |

这个 case 呈现**双峰分布**：要么 5/5（答案切题但缺依据），要么 2/2（答案基本没回答到问题）。不是围绕某个中心值的抖动，而是 Agent 在两种不同的作答模式之间切换。根因是知识库里 Chroma 的资料不足，模型在「承认资料不足」和「用行业常识补全」之间摇摆。

**这不是提示词能单独解决的问题**——证据本身就不存在。

### `agent_framework_multi_source`（0/5）

| 运行 | 相关性 | 完整性 | groundedness |
|---|---:|---:|---:|
| 1 | 5 | 4 | 3 |
| 2 | 4 | 3 | 3 |
| 3 | 5 | 4 | 3 |
| 4 | 5 | 3 | 2 |
| 5 | 5 | 4 | 3 |

最稳定的一个：相关性和格式一直很高，groundedness 一直不及格。Judge 反复指出的是引用错配与超出证据的推断（例如把证据里的 "supporting the OpenAI Responses API" 读成 "provider-agnostic, supporting 100+ other LLMs"）。

**这是三个里最适合用提示词修的**：证据存在，问题出在模型对证据的转述不忠实。

### `paged_attention`（2/5）

groundedness 在 3 和 4 之间来回跳，其余维度稳定。它不是明确的缺陷，而是**恰好压在 4 分阈值上**。用它来验证任何修改的效果都不可靠——5 次里 2 次通过，改与不改的差异会被这个方差淹没。

## 方法论结论

1. **单次 LLM-as-Judge 结果不足以支撑优化决策。** 同一份代码，`chroma_vs_qdrant` 在不同运行里拿过 5/5/4（通过）和 2/2/2（严重失败）。
2. **重复运行能区分三种情况**：稳定缺陷（0/5）、阈值抖动（2/5）、以及噪声导致的假性失败。基线报告把这三种混为一谈。
3. **修复效果必须用同样的重复运行来验证**，否则「改完通过了」可能只是抽中一次好运气。

## 下一步

优先修 `agent_framework_multi_source`：它是唯一「证据充分但转述不忠实」的稳定缺陷，属于提示词能影响的范围。修改后用相同的 `--repeat 5` 复测，用 0/5 → N/5 的变化判断是否真的改善。

`chroma_vs_qdrant` 的根因是语料缺失，应作为独立问题处理（补充 Chroma 文档后重建索引，或把它从答案质量集移到「知识边界」测试集，验证模型是否会正确拒答）。

`paged_attention` 暂不作为优化目标，它的方差不足以支撑结论。

## 证据边界

- 每个 case 5 次，样本量仍然很小，比例的置信区间很宽；0/5 只能说明「不容易通过」，不能读成「通过率为 0」。
- Judge 与 Agent 同模型，存在自评偏差。
- 未修改阈值、case 内容或 Agent 提示词——本轮只测量，不优化。
